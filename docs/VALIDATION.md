# Перевірка LumenVale 2.6.0

Це звіт про виконані перевірки пакета. Повний запуск нового пакета у Minecraft, точна сцена користувача та ігровий FPS ще потребують перевірки.

| Перевірка | Результат |
|---|---|
| Офлайн-компіляція та зв’язування | 828 графічних і 792 обчислювальні конфігурації; 0 помилок |
| Компіляція драйвером NVIDIA | 276 графічних і 264 обчислювальні конфігурації; пройдено |
| Синтетична сцена | 30 варіантів освітлення, вимірів, води й профілів; скінченні HDR-значення, без помилок OpenGL |
| Регресії перешкод | 16 контрольних випадків: кути, непряме світло, туман, плити, діагональні промені, скло й метадані прямого поля |
| Неповні блоки | Захоплення геометрії плити, килима та сходів; перевірено 40 станів дубових сходів |
| Обидві руки | Окремі кольори, додавання двох джерел, основна ліва рука, стіни й забарвлення склом |
| Відбиття | У контрольній кімнаті зникли смуги старої версії, збереглося відбиття світної панелі |
| Сумісність Iris | 9 офіційних JAR, 36 конфігурацій профілів, 468 джерел через оригінальний JCPP, 104 унікальні стадії скомпільовано; [матриця](COMPATIBILITY.md) |
| Спрощений режим | 276 графічних і 264 обчислювальні конфігурації на GPU, відсутні воксельні uniform, ручна ліва рука |

Тести виконано на NVIDIA GeForce RTX 4060 Laptop GPU / OpenGL 4.6. У тестах парсерів Iris залежний від гри хост обходився або замінювався тестовим об’єктом; рендерер Iris у Minecraft не запускався. Формат очищення й таблиця форм залишилися незмінними; результати їхніх попередніх відокремлених тестів позначено у звіті як історичні та перевірено поточною матрицею ресурсів.

В Ultra залишаються 22 обчислювальні проходи. Сім воксельних полів займають 15 МіБ; таблиця форм — ще 37 600 байтів. Маска геометрії використовує наявний альфа-канал фінального прямого поля. Тест усіх 13 прямих стадій на контрольному об’ємі підтвердив побітово однакові RGB з 2.5.0 та правильну нову маску. Карти тіней, екранні буфери та пам’ять гри до цих чисел не входять.

Докладні результати: [VALIDATION.json](../VALIDATION.json). Обмеження: [README_UA.md](../README_UA.md).

## Відтворені витоки

Порівняно справжній GLSL із незміненого ZIP 2.5.0 і поточних джерел на однакових даних. У закритому куті поверхня давала RGB 0.4585, туман 0.25, а передача світла з рук — 1.0. У 2.6.0 всі три результати нульові. Туман під зайнятою частиною плити змінився з 0.9766 до 0, а над відкритою частиною зберіг 2.0. Додатково перевірено непряме світло, кут зі сполученим повітрям, перетин трьох осей в обох напрямках, спільний край плит, внутрішність повного блока та залишкову ванільну складову. Контрольне кольорове скло зберегло спектр передачі.

Ці перевірки усувають конкретні помилки вибірки й обходу комірок. Поширення поля все ще має крок в один блок і маски отворів 4×4; воно не моделює всі промені всередині довільної форми. Перевірка перешкод для переносного світла потребує воксельного режиму Ultra.

## Вартість вибірки

RTX 4060 Laptop GPU, 960×540, однакова синтетична функція поверхні, 24 малювання в запиті таймера, медіана дев’яти вимірів після прогріву:

| Дані навколо точки | 2.5.0, мс | 2.6.0, мс |
|---|---:|---:|
| Повітря | 0.1484 | 0.0146 |
| Звичайна підлога | 0.1714 | 0.0802 |
| Повні світні блоки | 0.1747 | 0.1143 |
| Часткові плити | 0.6009 | 1.1181 |
| Межа об’єму | 0.0857 | 0.0105 |

Це вартість окремої функції, не всього кадру й не FPS Minecraft. Точна перевірка проміжних форм дорожча у випадку плит. Порівняння біля плит навмисно має значну різницю HDR усередині зайнятої частини: старий код помилково повертав там світло, новий — нуль. У відкритій частині різниця вкладається в поріг 0.012 HDR. Апаратна інтерполяція має інше округлення; побітова тотожність усієї вибірки не заявляється.

## Повторення перевірок

```sh
python scripts/validate.py --glslang /path/to/glslangValidator
python scripts/check_compatibility.py --glslang /path/to/glslangValidator
python -m pip install -r scripts/gpu-requirements.txt
python scripts/test_voxel_occlusion.py
python scripts/build.py
python scripts/check_repository.py
```

Для компіляції й пакування потрібні Python 3.10+, JDK 21 та glslang. Тест перешкод із зафіксованими залежностями потребує Python 3.11+ і OpenGL 4.3 compatibility. На Linux встанови GLFW, Mesa, Xvfb та xauth і запусти `LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a python scripts/test_voxel_occlusion.py`. Він використовує реальний GLSL і таблицю форм, не потребує Minecraft та не є тестом швидкодії програмного рендерера. Звіт записується в `.validation/occlusion/result.json`.

Матриця завантажує офіційні Iris JAR і хешовані залежності тестового хоста, виконує оригінальні парсери та JCPP. Без `--glslang` компіляцію явно позначено пропущеною. Повна нативна синтетична сцена та таймери RTX наведені у VALIDATION.json і не відтворюються портативним тестом перешкод.

GitHub Actions запускає компіляцію, матрицю, тест перешкод на Mesa та перевірку дистрибутива для push у main і для pull request. Звіти та ZIP доступні в артефактах запуску сім днів. Це не додає статусу ігрової перевірки до матриці сумісності.
